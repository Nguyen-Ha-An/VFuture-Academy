# Academy Canvas workspace redesign

## Implemented scope

Authenticated Academy workspaces use a persistent narrow VFuture global rail, contextual staff/course navigation, neutral surfaces, the existing teal identity, English/Vietnamese controls, dark/light themes and mobile layouts. Legacy URLs, permissions, learner histories, exams, attempts, timers, notebooks, certificates, review and versioned publication remain supported. Public marketing, authentication, identity, infrastructure, cost controls, discussions, inbox, cohorts, attendance and integrations are outside this change.

The task-first learner dashboard prioritizes coursework, real course/status filters and data-backed counts, then recorded results and compact course continuation. Published announcements form the secondary column; unavailable or empty data stays explicit. The course workspace uses a secondary left navigation rail for Overview, Modules, Assignments, Grades, Announcements and Calendar, with a mobile drawer rather than route tabs. No unsupported people panel, invented missing-work policy, or weighted course grade is added. `/app/tasks` includes unscheduled work and retained submission states; `/app/results` shows recorded scores without invented weighted totals. Calendars project separate assignment schedules and pinned exam open/close windows, with desktop month and mobile agenda presentations in Asia/Ho_Chi_Minh. Assignment histories and instructor queues/details display the recorded submission-time deadline and explicit late flag; unknown historical lateness stays unknown and no penalty is inferred.

Studio defaults to a visual editor alongside JSON, with the mode remembered locally for course and question-bank authoring. Existing raw source remains authoritative. Course forms mutate the existing WorkspaceState through its source-change pipeline; bank forms use its existing text/autosave state. Visual actions reject malformed, duplicate-key and stale JSON, retain identifiers/references/bilingual values, and preserve autosave, recovery, conflicts, diagnostics, review, versioned publication and renderer previews. Native local Tabs separate Visual/JSON/Preview, TreeBrowser organizes the course outline, and meaningful form sections put titles and content before advanced technical metadata. Short text, long content, numeric fields and primitive arrays use appropriate controls. Resource and opportunity authoring has structured bilingual content; project team/output rows use a lossless, backward-compatible codec for pipes, backslashes and embedded newlines. Bank previews derive from current valid source, not only the last saved record. Schema-driven forms cover the current document, lesson-block and question variants; a schema-walking test checks explicit EN/VI labels for all 197 published schema property names and palette/enum choices.

Teaching grading uses a response-first workspace, compact learner/attempt/version context, a single rubric total and pinned draft/completion actions; completed results remain distinct from draft and release authority. Administration and supporting profile, leaderboard, projects, resources, opportunities and certificate surfaces share the workspace panels, native responsive tables, controls and states. Waiting work takes precedence over historical charts; phone rows retain school/role/status information and accessible actions. The active permission-derived Central or school context remains visible on phones. Role-version conflicts preserve drafts and require explicit reload and review before a new save. Analytics uses proper description-list markup and keyboard-accessible table overflow.

## Actual Instructure UI layer

All direct Instructure dependencies are pinned to **11.7.10**. SideNavBar, DrawerLayout, Table/Responsive, Tabs, TreeBrowser, FormFieldGroup, RadioInput, NumberInput and Progress are used for actual navigation, composition, data and editing workflows, alongside the controls below. `src/features/canvas/ui` wraps the actual `/v11_7` Button/IconButton, TextInput, TextArea, SimpleSelect, Checkbox, Link, Alert and Spinner exports. `@instructure/emotion` supplies InstUISettingsProvider and the per-tree Emotion cache; the light/dark themes retain VFuture's teal through the documented theme-token overrides. The provider wraps the authenticated learner and current staff shells. Live learner/staff theme changes update existing controls without remounting forms or losing work.

The adapters preserve native form requirements, disabled/read-only states, explicit button type, DOM refs and Radix trigger keyboard/focus behavior. Button content preserves inline icon/text composition. Cards and controls use a coherent compact radius; status chips alone use pill shapes. Select popovers mount within their owning modal, preserve caller refs/mounts, and close options on the first Escape before the enclosing dialog. Always-open desktop course navigation does not take focus; mobile drawers retain containment and return focus, and resizing does not remount the course content. Existing Radix menus/dialogs and Next Link wrappers remain interoperable where their interaction or navigation contract is required. Generic public/authentication primitives are unchanged.

`npm run verify:instui` runs a separate tiny **Next 15.5.25 / React 19.1.0** application in `tests/e2e/instui-next-harness`. Its Chromium contract covers the actual learner/staff shells and course layout, rich native components, server-rendered Emotion styles and server children, client hydration/state, exact teal light/dark colors, text/select/checkbox interactions, inline icon layout, primary hover contrast, native keyboard navigation, responsive tables and modal Select pointer/Escape/focus behavior. Browser, page and hydration errors are asserted explicitly. The proof resolves its async query reader inside an explicit server Suspense boundary and compares React IDs from the actual navigation response with hydrated client hook values. Cold and warm local dev requests, plus the unchanged async page pattern under a local Next production build, were checked separately; this is not hosted production evidence. InstUI element-based Responsive intentionally renders a measurement wrapper on the server; its data table is tested after client measurement, not represented as non-JavaScript server-rendered rows. A pinned-library exact-width-return observer defect is handled in the source adapter without vendor edits or remounting native children, with state/focus and observer-cleanup regressions. There is no production proof route. Its generated `.next` tree is explicitly ignored and excluded from Graphify.

## School teaching data and authorization

New learner GET endpoints are `/api/v1/learning/tasks`, `/results`, `/calendar` and `/announcements`. New teaching options, announcement CRUD/publish/archive and schedule endpoints live under `/api/v1/teaching`. Input/output contracts are typed and validated.

Announcements belong to a school and course, with draft, explicit publish and archive transitions. Draft deletion is restricted to a service-role RPC. There is no email, push, reply or discussion side effect. Mutable schedules are separate from immutable course content and keyed by school + published course version + assignment identity; an embedded assignment includes its block ID. Existing content starts unscheduled. Optional deadlines are UTC timestamps with explicit Asia/Ho_Chi_Minh authoring/display. An insert trigger snapshots the deadline/late state onto a new submission; schedule changes, legacy rows and idempotent retries cannot rewrite that history.

Dedicated teaching permissions are checked for the requested or persisted school. Teachers and Central Admin operating in a selected school may author; School Admin alone receives no new authoring authority. Navigation admission grants no action authority. Server reads/mutations check membership, course availability or enrollment-pinned historical versions, and the enrollment-owned school boundary. Unknown historical schools are not guessed. Archived pinned courses remain available where needed, and existing announcements can be archived/deleted without depending on current public course availability.

The forward migrations are `supabase/migrations/20261105000000_teaching_canvas.sql` and `20261105010000_teaching_announcement_revisions.sql`. Announcement edits, publishing, archiving and draft deletion require the last confirmed positive integer revision. The database advances revisions atomically; conditional mutations return a stale conflict rather than publishing an unseen concurrent edit. Forms retain unsaved text, guard context/navigation changes, and do not publish while local edits differ from the last confirmed saved revision. Mutation and audit writes commit atomically; audit metadata excludes announcement body text. `scripts/verify-teaching-canvas.mjs` checks the migration chain, role privileges, authenticated-table denial, accepted late submissions, deadline snapshots, retries, immutability and rollback on audit failure using disposable local PostgreSQL fixtures. It is included in `verify:local`.

The [route review inventory](./route-review.json) distinguishes 85 source page entrypoints: 53 substantive rendering entries, one not-found boundary and 31 aliases. Actual owning components and redirect-function contracts are distinguished from generic fixture fallbacks; a successful URL response is not screen coverage. Review fixtures include sparse/dense/empty/failure, school/permission, pending, stale-revision and retry states as appropriate. These are local fixture contracts, not live database, hosted capacity or deployment evidence. Synthetic fixture state and metrics are not live Azure data or telemetry. Notebook workspace/runtime-interface checks use controlled local sessions and an iframe stand-in; they are not proof of hosted Jupyter/Python execution. Azure account UI flows use local transports and do not establish actual provisioning, credential delivery or recovery. Media-link display does not establish hosted private-file retrieval.

File-only unsupported-format coverage does not establish semantic relationships; static AST edges are not runtime authorization proof.
